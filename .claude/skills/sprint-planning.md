# 스프린트 플래닝 (Sprint Planning)

## 스킬 설명
스크럼 팀이 다음 스프린트에서 무엇을, 어떻게 할지 결정하는 계획 회의를 준비하고 진행하는 스킬이다.
백로그 정제부터 스프린트 목표 수립, 용량 기반 작업 배분까지 실행 가능한 플래닝 산출물을 만든다.

## 사용 시점
- 새로운 스프린트를 시작하기 전 계획을 수립할 때
- 팀 용량 대비 현실적인 작업량을 산정해야 할 때
- 스프린트 목표(Sprint Goal)를 팀과 정렬할 때
- 백로그 아이템을 실행 가능한 태스크로 분해할 때

---

## 실행 지침

### Step 1: 백로그 정제 (Backlog Refinement)

플래닝 전 백로그 상태 점검:
- [ ] 상위 10개 아이템에 Acceptance Criteria가 있는가?
- [ ] 스토리 포인트가 추정되어 있는가?
- [ ] 8포인트 이상 항목은 분해되었는가?
- [ ] 의존성이 명시되어 있는가?

**DEEP 기준 (정제 완료 체크리스트):**
| 기준 | 의미 |
|------|------|
| **D**etailed enough | 팀이 작업 내용을 이해하는가 |
| **E**stimated | 스토리 포인트가 추정되었는가 |
| **E**mergent | 상위 아이템이 더 상세한가 |
| **P**rioritized | 비즈니스 가치 기준으로 정렬되었는가 |

### Step 2: 팀 용량 계산 (Team Capacity)

```
스프린트 용량 = Σ (개인별 가용 일수 × 개인 포커스 팩터)
포커스 팩터 기본값: 0.7 ~ 0.8 (회의, 리뷰, 기타 업무 제외)
```

| 계산 항목 | 내용 |
|-----------|------|
| 스프린트 기간 | 보통 2주 (10 영업일) |
| 공휴일/휴가 제외 | 개인별 부재 일수 차감 |
| 포커스 팩터 | 실제 개발 가능 비율 (팀 히스토리 참고) |
| 가용 포인트 | 팀 평균 벨로시티와 비교 검증 |

**벨로시티 기반 검증:**
- 최근 3스프린트 평균 벨로시티를 기준으로 삼는다
- 첫 스프린트는 예상 용량의 80%로 보수적으로 계획한다

### Step 3: 스프린트 목표 수립 (Sprint Goal)

**좋은 스프린트 목표 조건:**
- 단일 문장으로 표현 가능한 비즈니스 가치
- 팀 전체가 공동으로 달성 가능한 목표
- 스프린트 종료 시 달성 여부를 명확히 판단할 수 있음
- 프로덕트 오너와 개발팀이 함께 도출

**템플릿:**
```
이번 스프린트에서 우리는 [대상 사용자]가 [핵심 기능/가치]를
[사용할 수 있도록/경험할 수 있도록] 한다.
성공 지표: [측정 가능한 완료 조건]
```

### Step 4: 스프린트 백로그 구성

**선택 기준 (순서대로 적용):**
1. 스프린트 목표에 직접 기여하는 스토리 먼저 선택
2. 팀 용량(포인트) 내에서 선택
3. 의존성 있는 아이템은 선행 작업과 함께 묶어서 선택
4. 버그/기술 부채는 전체의 20% 이하로 제한

**태스크 분해 (Task Breakdown):**
각 유저스토리를 1일 이내 완료 가능한 태스크로 분해:
```
유저스토리 → [설계 태스크] + [개발 태스크] + [테스트 태스크]
각 태스크: 이상적 시간 4~8시간 이내
```

### Step 5: 플래닝 리스크 점검

| 리스크 | 체크 항목 |
|--------|---------|
| 오버커밋 | 선택 포인트 > 벨로시티 × 1.1 이면 경고 |
| 단일 병목 | 특정 팀원에게 작업이 집중되지 않는가 |
| 미정의 의존성 | 외부 팀 연동, API 스펙 미확정 항목 |
| 큰 스토리 | 5포인트 이상 스토리가 50% 초과하면 재분해 권장 |

### 리스크 및 의존성
- US-14는 US-12 완료 후 착수 가능 (의존성 존재)
- 디자인 시안 미확정: 온보딩 화면 디자인 확인 필요 (담당: 디자이너C, 기한: D+2)

### 제외 항목 (이번 스프린트 외)
- US-15 (소셜 공유 기능): 목표와 직접 연관 없어 다음 스프린트로 이동

## 품질 기준
- [ ] 스프린트 목표가 단일 비즈니스 가치 문장으로 표현된다
- [ ] 선택 포인트가 팀 벨로시티 ±10% 이내다
- [ ] 모든 스토리에 담당자가 배정된다
- [ ] 의존성과 리스크가 명시된다
- [ ] 제외 항목과 사유가 기록된다
