# 스킬 제작 (Skill Creator)

## 핵심 루프

```
의도 파악 → 인터뷰/리서치 → 스킬 초안 작성 → 테스트 실행 → 결과 평가 → 개선 반복
```

---

## Step 1: 의도 파악

다음 네 가지를 명확히 한다:

1. 이 스킬로 무엇을 할 수 있어야 하는가?
2. 어떤 상황/문구에서 트리거되어야 하는가?
3. 출력 형식은 무엇인가?
4. 객관적으로 검증 가능한 출력인가? (그렇다면 테스트 케이스 작성 권장)

대화 히스토리에서 이미 답이 있다면 먼저 추출하고, 빠진 부분만 사용자에게 확인한다.

---

## Step 2: 스킬 파일 구조

이 프로젝트의 스킬은 `.claude/skills/` 아래 단일 마크다운 파일로 작성한다.

```
.claude/skills/
└── skill-name.md       ← 필수 (frontmatter + 본문)
```

**frontmatter 필수 항목:**
```yaml
---
name: skill-name
description: |
  스킬이 하는 일과 트리거 조건을 모두 포함한다.
  "언제 사용하는가"는 반드시 여기에 — 본문이 아니라 여기에 적는다.
  (본문은 트리거 이후에만 로드되므로 여기 없으면 무의미)
agent: execution | strategy | discovery   ← 담당 에이전트
---
```

**본문 권장 구조:**
```markdown
# 스킬명

## 스킬 설명
(1-2문장 요약)

## 사용 시점
(목록형)

---

## 실행 지침

### Step N: ...
(단계별 절차)

---

## 출력 형식 예시
(실제 출력 예시 — 코드블록)

---

## 품질 기준
- [ ] 체크리스트
```

---

## Step 3: 좋은 스킬 작성 원칙

**간결성이 핵심**: context window는 공유 자원이다. Claude가 이미 아는 것은 쓰지 않는다.

**자유도 설정**:
| 자유도 | 사용 시점 | 표현 방식 |
|--------|---------|---------|
| 높음 | 여러 접근이 유효할 때 | 텍스트 지침 |
| 중간 | 선호 패턴이 있지만 변형 허용 | 의사코드 + 파라미터 |
| 낮음 | 오류에 민감하거나 일관성 필수 | 구체적 절차, 예시 |

**설명 작성 시 주의사항**:
- description은 트리거 메커니즘이다 — 구체적이고 포괄적으로 작성
- MUST/ALWAYS 남발 대신 **왜** 중요한지 설명하는 방식 선호
- 출력 형식은 예시로 보여주는 것이 설명보다 효과적

**500줄 제한**: 본문이 길어지면 references 파일로 분리하고 SKILL.md에서 참조

---

## Step 4: 테스트 케이스 작성

스킬 초안 완성 후 현실적인 테스트 케이스 2~3개를 작성한다.

```markdown
## 테스트 케이스

**TC-01: [케이스 이름]**
- 입력: "[실제 사용자가 입력할 법한 문장]"
- 기대 출력: [출력 형식 및 포함되어야 할 항목]
- 검증 기준: [ ] 항목1, [ ] 항목2

**TC-02: ...**
```

테스트 케이스 작성 기준:
- 실제 사용자가 쓸 법한 자연스러운 문장
- 명확한 케이스뿐 아니라 엣지 케이스도 포함
- 주관적 판단이 필요한 스킬은 테스트 케이스 생략 가능

---

## Step 5: 품질 검증 체크리스트

스킬 파일 완성 후 아래를 점검한다:

**구조 검증**
- [ ] frontmatter에 `name`, `description`, `agent` 필드가 있는가
- [ ] `description`에 "언제 트리거되는지"가 명시되어 있는가
- [ ] 본문에 `사용 시점`, `실행 지침`, `출력 형식 예시`, `품질 기준`이 있는가

**내용 검증**
- [ ] 단계별 절차가 명확하고 실행 가능한가
- [ ] 출력 형식 예시가 실제 사용에 충분히 구체적인가
- [ ] Claude가 이미 아는 내용을 불필요하게 반복하지 않는가
- [ ] 500줄 이내인가 (초과 시 분리 고려)

**에이전트 연동 검증**
- [ ] 담당 에이전트 파일에 이 스킬이 `skills:` 목록에 추가되었는가
- [ ] 에이전트의 "요청 유형별 접근"에 트리거 조건이 추가되었는가

---

## Step 6: 에이전트 연동

스킬 파일 생성 후 반드시 담당 에이전트(`.claude/agents/`)를 업데이트한다:

```yaml
# 에이전트 frontmatter에 추가
skills:
  - existing-skill
  - new-skill-name    ← 추가
```

에이전트 본문에도 추가:
```markdown
## 담당 스킬
- **new-skill-name**: 한 줄 설명

## 실행 원칙 > 요청 유형별 접근
- **[트리거 요청] 요청** → new-skill-name 스킬 실행
```

## 개선 반복 원칙

피드백 기반 개선 시:
1. **일반화**: 특정 예시에만 맞는 수정이 아닌, 재사용 가능한 패턴으로 개선
2. **군살 제거**: 효과 없는 지침은 삭제 — 짧을수록 좋다
3. **이유 설명**: "하지 마라" 대신 "왜 이것이 중요한지" 설명
4. **반복 패턴 발견**: 여러 케이스에서 공통으로 필요한 것은 스킬에 내재화
